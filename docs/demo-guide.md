# 项目演示与答辩流程

## 演示顺序

1. 游客打开首页和鱼类图鉴，说明公开接口不需要登录。
2. 注册普通用户并登录，说明密码由 BCrypt 保存，前端使用 JWT 调用受保护接口。
3. 上传鱼类图片，展示 YOLO 检测框、类别、置信度和识别历史。
4. 若模型类别未在鱼类资料库中，展示管理员“识别待办”。
5. 普通用户上传现场图片并创建救助工单。
6. 管理员审核公开，志愿者接单并提交完成反馈，管理员最终验收。
7. 用户提交鱼类资料新增或纠错申请，管理员审核后写入正式资料库。
8. 展示管理员统计页、用户启停和逻辑删除。

## 一分钟项目介绍

本项目是一个前后端分离的海洋鱼类智能化信息管理系统。后端使用 Spring Boot、Spring Security、JWT、MyBatis-Plus 和 MySQL，前端使用 Vue 3、TypeScript、Pinia、Axios 和 Element Plus，AI 服务使用 FastAPI 和 Ultralytics YOLO。系统围绕鱼类知识管理、图片识别和公益救助三个核心场景，设计了普通用户、志愿者和管理员三类角色，并实现了申请、审核、接单、反馈、验收等完整业务状态流转。

## 面试深挖要点

- 为什么使用三层结构：Controller 接收请求，Service 处理业务和事务，Mapper 操作数据库，职责清晰且便于测试。
- 为什么 AI 独立部署：Python 更适合模型推理，Java 更适合业务系统；通过接口解耦，模型替换不影响用户和工单模块。
- 如何保证工单不被重复操作：数据库更新时同时判断原状态，只有符合预期状态的记录才能更新成功。
- 如何实现权限：JWT 保存用户编号和角色；Spring Security 先做接口鉴权，Service 再检查数据库中的账号和角色状态。
- 图片为什么存地址：数据库保存相对路径，文件存磁盘或对象存储，避免数据库体积快速膨胀。
- 如何保证质量：参数校验、统一异常处理、事务、逻辑删除、状态机和自动化测试共同保证业务可靠性。
